## 真实浏览器和数据库

测试笔记标题及正文明确标为独立合成验收，来源 URL 是公开论文链接，
不表示这些合成段落为论文原文，也不是使用者效果数据。

1. 基线从干净 Git 导出启动，真实笔记滚动20%后服务进程重启，阅读器恢复20%。
   标记已读后 SQL 为 read/100，但原搜索卡仍 reading/20。
2. 基线受控停止本任务数据库，检索返回 ECONNREFUSED，顶栏却仍绿色。
   [基线截图](baseline-stale-health.png)。
3. 修复版拒绝 ftp://x 导入，且校验失败不将连接提示变红；正常 HTTPS 导入成功。
4. 检索“注意力”返回真实保存的标题、来源、高亮片段。阅读器 PageDown 到10%，
   关闭后卡片同步为阅读中/10%；仅重启该服务进程后，重新打开仍恢复10%。
   [恢复截图](fixed-resume.png)。未据此次手动操作宣称测得小于800ms关闭延迟。
5. 阅读中筛选打开该笔记，标记已读并关闭，该笔记移出当前筛选；
   原搜索卡同步为已读、100%。[卡片截图](fixed-card.png)。
6. 只停止本任务独立容器，点击检索，顶栏同步为数据库不可用，操作显示真实错误。
   [断库截图](fixed-down.png)。
7. 启动同一容器，直接重试检索（不刷新页面），顶栏恢复已连接并显示真实卡片。
   [恢复连接截图](fixed-recovered.png)。

## 整分支复核后的补充

独立审阅以只读方式检查原始分支并复跑离线29项。其重要发现都在同一修复阶段
通过先失败后成功的回归覆盖，没有将审阅意见直接当作已修复证据：

- 空白/单字符查询不访问数据库，其成功响应不再改变连接判断。
- 搜索请求在途时发生的已确认保存，按笔记 id 和保存版本覆盖旧快照；第二条笔记保持原状。
- 保存失败时阅读器标明「未保存」，关闭后全局警告保留，并允许恢复连接后重试相同意图。
- 启动健康错误与较新的连接结果统一，恢复后清除过期启动错误。
- 笔记库明确请求200条，避免继承现有 API 省略 limit 时的一条默认值；后端接口未改。

真实浏览器补充确认空检索在断库时保持红色提示：[截图](tokenless-down.png)。
第三条合成笔记「独立浏览器补充 · 失败重试」从未读开始，断库标记已读后，
阅读器显示已读（未保存）；关闭后原卡仍未读，且全局失败警告可见：
[失败截图](save-failed.png)。恢复数据库后点击重试，卡片才变为已读/100%，
警告消失；切换笔记库可同时看到三条：[成功截图](retry-success.png)。
该第三条 id 为 `82101df3-e487-4536-848f-4d2fa24100eb`，最终 SQL 也为 read/100。

重要边界：失败修改仅保留于当前页面内存，刷新/离开前必须保存；本地单人应用
没有账号隔离。列表当前最多200条、无翻页，超出可使用全库候选检索。
